# Wazuh

Only the **Wazuh Agent** (client running on monitored machines) is built. Wazuh Manager is out of scope.

For the corresponding NixOS module, see `nixos/services/wazuh/agent.nix`.

## Updating

When bumping the Wazuh package version, be aware that `dependencyVersion` might need an update and dependency specs have to be re-generated by our prefetch script.

If a build fails, check the errors we've already encountered below.

### Choosing dependencyVersion

`dependencyVersion` in `agent/default.nix` (passthru) is the single source of truth — the prefetch script reads it from there.

1. In the Wazuh codebase: open `src/Makefile` and search for the `packages.wazuh.com/deps/<dependencyVersion>/libraries` download URLs — the number in those URLs is the version we're looking for.
2. Set `dependencyVersion` in `agent/default.nix`.
3. Run `agent/prefetch-external-dependencies.sh` and commit the regenerated `agent/external-dependencies.nix`.

### External-dependencies failure

If `make deps` fails with something like:

```sh
make: *** [Makefile:<line>: external/<dependency>.tar.gz] Error 6
```

the build tried to download a dependency at build time. In the Nix sandbox there is no network access, and the Makefile's download rules abort — the `|| true` guards only cover the `external-precompiled/` staging variant, not the `external/%.tar.gz` rules. We prefetch all agent dependencies with `fetchurl` and unpack them into `src/external/` in `postUnpack`, so the `test -d external/<dependency>` checks short-circuit and no download is ever attempted.

Seeing this error therefore means a dependency of the agent build is missing from our prefetch list (or was renamed upstream): add its name to the `EXTERNAL_DEPS` array in `agent/prefetch-external-dependencies.sh` and run the script. The failing target lives in the `external/*.tar.gz` download rules in `src/Makefile` — search for it there.

### libbpf-bootstrap tarball changes

Upstream may change the tarball structure on `packages.wazuh.com` (member paths, `./` prefixes); the `postUnpack` extraction in `agent/default.nix` depends on it via `--strip-components=2` (see the comment there). If this step breaks after a dependency bump, two hashes are involved: the regenerated one in `agent/external-dependencies.nix` (updated by the prefetch script) and the manually maintained one in `agent/default.nix` (`passthru.libbpf_bootstrap_deps.cmakeLists`) — both fetch the same tarball, and both must match its current content.
